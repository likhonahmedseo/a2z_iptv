# Taste
- Works with WordPress Elementor sites and wants deliverable designs packaged as "headless" self-contained HTML snippets (no document shell — no `<!DOCTYPE>`/`<html>`/`<head>`/`<body>`/`<title>`/`<meta>`) that can be pasted directly into an Elementor HTML widget, keeping all sections and the original design intact and leaving the source file untouched. Confidence: 0.8
- When redesigning a website based on a sample/reference site, audits the reference first and keeps the original content intact — real copy, pricing, and working links (including cart/CTA URLs) — rather than inventing new placeholder content. Confidence: 0.85
- Wants every link on all delivered pages to be a real, working URL — source of truth is the live site's sitemaps (e.g., product-sitemap.xml / sitemap_index.xml) and live page HTML — and explicitly asks for an audit pass across every page created to replace placeholder/dead links (`#`, empty `wa.me/`, or messaging links standing in for checkout/Buy-Now buttons) with canonical ones. Confidence: 0.95
- When rebuilding a niche website (e.g., IPTV/streaming), prefers adding extra related sections beyond the reference (stats, how-it-works, devices, testimonials, payment methods, expanded FAQ) so the page feels complete, not a minimal clone. Confidence: 0.8
- Prefers a dark, premium "cinematic" UI for streaming/entertainment sites — dark background, accent-color glows, animations, and interactive touches (mobile menu, accordions, counters, marquees). Confidence: 0.5
- Prefers real brand/asset images (e.g., actual payment-method logos, channel images pulled from the reference/live site) over generic icon-font approximations or placeholder text tiles. Confidence: 0.85
- For image-gallery/carousel sections, prefers a seamless, endless horizontal auto-scrolling marquee (single line, left-to-right, no visible scrollbar, no end tail/gap) that loops continuously. Confidence: 0.85
- For content-carousel/slider sections (reviews, testimonials) expects BOTH working prev/next arrow controls AND auto-advance — an auto-playing loop (advance every few seconds) that wraps around at the ends without getting stuck, pauses on hover/interaction, and resumes after an idle delay. Confidence: 0.7
- When the site is deployed as an Elementor/WordPress site, JS that drives embedded sections (carousels, logo swaps) must be scoped to the `.a2z-elementor-fragment` (falling back to `document`) and run via `DOMContentLoaded`/`load`, not top-level `document` queries at parse time — mirroring the CSS-scoping rule so live-site behavior matches the local standalone file. Confidence: 0.75
- External asset dependence (e.g., favicon-logo URLs like `icons.duckduckgo.com`) is unreliable on live sites — expects a guaranteed fallback (e.g., an `onerror` handler restoring the original FontAwesome icon) so a card never renders an empty/missing box. Confidence: 0.7
- Implements image/JS error fallbacks with programmatic listeners (`img.addEventListener('error', ...)` / DOM APIs) rather than inline `onerror` attribute strings — escaped/nested quotes inside an HTML attribute get mangled by the parser and silently break the handler, so build DOM nodes imperatively and bind listeners in-closure instead. Confidence: 0.7
- Sets the quality bar for site work as "make the best UI and UX" across every page of a multi-page site — expects not just working links but also polish passes (consistent CTAs, anchor-scroll offsets so fixed navbars don't cover section headings, fix interaction bugs like toggles/reveal animations, and touch-device behavior for hover-dependent effects) applied site-wide, not per-page. Confidence: 0.8
- Every fix or change request is expected to be propagated to ALL pages of a multi-page deliverable — user explicitly reiterates "for all pages" and follows up ("did you apply all the last css changes to all the pages") to verify changes were applied globally, not just to the reported page. Confidence: 0.9
- Tests delivered pages in the live host environment AND in incognito/guest mode, and expects designs to render correctly for public visitors — pages must not depend on JS-driven styling (e.g., Tailwind CDN) or anything that can be delayed/blocked/stripped for non-logged-in users; styling should be compiled to self-contained static CSS embedded in each fragment. Confidence: 0.85
- When a fragment is embedded into an existing WordPress/Elementor theme, expects its styles to be scoped so the host theme cannot override the delivered design (e.g., link colors/underline changing on hover) — the live-site look must match the designed look. Confidence: 0.7
- When adding a new page to an existing site, expects the design to follow the other existing pages ("follow other pages design") — reuse the established design language and section patterns rather than introducing a new/standalone style. Confidence: 0.7
- Treats copy the user supplies as authoritative and expects it reproduced verbatim ("content should be same to same") — do not paraphrase, restructure, or editorialize the provided text. Confidence: 0.7
- Wants SEO-friendly, contextual internal interlinks added to content pages — wrap existing anchor phrases in links rather than inserting new visible copy (content must stay unchanged, "without changing the content") — with links drawn from the site's real sitemap and chosen so they read naturally in context; avoids forced/non-contextual link stuffing (skips URLs lacking a natural anchor rather than forcing them). Confidence: 0.8
- Expects exactly one external (outbound) link where requested, to a real, verified-live URL (explicitly not a "fake/dummy or 404" URL), tailored to the page's topic. Confidence: 0.7
- Wants clean canonical URLs free of query/tracking parameters in links — explicitly rejects "ChatGPT parameters" such as `?utm_source`/`?utm_medium`/`?utm_campaign` (and similar tracking query strings); links should be plain trailing-slash URLs. Confidence: 0.7
- Expects frontend/HTML deliverables to be verified by actually rendering them in a real headless browser (readily installs tooling such as `agent-browser` when offered) — wants visual/screenshot checks of each section plus responsive/mobile-viewport checks, not static tag-balance or file-level inspection alone. Confidence: 0.7
